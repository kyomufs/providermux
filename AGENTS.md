# AGENTS.md — providermux

Правила работы с этим репозиторием. Дополняют общие инструкции; при расхождении
действуют они.

## Коммуникация

Русский язык в ответах пользователю. Код, комментарии, коммиты и документация —
на английском.

Комментарии в коде объясняют **почему**, а не что: что видно из кода и так.
Знание, добытое измерением или чтением чужих исходников, ценно — держать его
рядом с решением. Перечислять очевидное не нужно.

## Сборка, коммит и пуш — делает агент, сам

**Это главное правило репозитория.** Никаких напоминаний не требуется: после
каждого законченного изменения агент сам проходит полный цикл и публикует
результат.

### Полный цикл

```sh
# 1. Форматирование — обязано быть чистым
gofmt -l .                       # пусто = хорошо; иначе gofmt -w .

# 2. Разбор и тесты
CGO_ENABLED=0 go vet ./...
CGO_ENABLED=0 go test ./... -count=1

# 3. Сборка

# Сборка бинаря с версией: `version` печатает её, а без неё — «неизвестно».
# Версия берётся из последнего коммита, поэтому воспроизводима.
CGO_ENABLED=0 go build \
  -ldflags "-X main.buildVersion=$(git rev-parse --short HEAD)" \
  -o ~/.local/bin/providermux ./cmd/providermux

# 4. Живая проверка — «собралось» не доказательство
/tmp/providermux up --listen 127.0.0.1:8795 &
sleep 1
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8795/v1/models   # 200
curl -s http://127.0.0.1:8795/_control/status | head -c 120

# 5. Публикация
git add -A
git status --short               # осмотреть, что попадает в коммит
git diff --cached --stat
```

### Где лежит установленный бинарь

`~/.local/bin/providermux` — и он на `PATH`. После каждой сборки его надо
обновлять: иначе CLI останется прежним, а запущенный демон — новым, и это
запутает при первой же отладке.

### Демон запускает тот бинарь, который собран

Сборка сама по себе не меняет то, что обслуживает порт: процесс стартовал со
старым файлом и переживёт сборку. Поэтому перезапуск — часть цикла, сразу после
сборки, без напоминаний:

```sh
systemctl --user restart providermux
sleep 2
systemctl --user show providermux -p MainPID -p ExecStart | head -2
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8787/v1/models   # 200
```

Юнит пишет home-manager, и на диске это симлинк в store: править его нельзя —
следующая активация вернёт своё. `ExecStart` на `~/.local/bin/providermux`
переопределён drop-in'ом
`~/.config/systemd/user/providermux.service.d/10-local-binary.conf`, который
home-manager не трогает. Если демон после перезапуска всё ещё показывает
store-путь — drop-in пропал, и это надо чинить, а не мириться.

Коммит и пуш:

```sh
git -c user.name="kyomufs" -c user.email="kyomufsdev@gmail.com" commit -F - <<'EOF'
<тип>: <что изменилось и почему>

<тело: причина, а не пересказ диффа>
EOF

git push origin main
```

Пуш идёт по SSH-ключу (`origin` = `git@github.com:kyomufs/providermux.git`).
Рецепт с `ghp_…` из `cordis.patch.yml` больше не работает: GitHub отвечает
`Invalid username or token`, то есть токен отозван, — измерено 2026-11-20.

`CGO_ENABLED=0` обязателен: в окружении нет C-компилятора, и без него сборка
падает на пакете `runtime/cgo`. Это же и целевой режим выпуска — статический
бинарь без зависимостей.

### Секреты

**Перед каждым коммитом:**

```sh
grep -rn "ghp_\|sk-[A-Za-z0-9]" --include="*.go" --include="*.md" . | head
```

Пусто — хорошо. Пуш идёт по SSH-ключу, поэтому токен в командах не участвует и
попадать в файлы ему неоткуда. Если в выводе появилась строка вида `ghp_…` или
`sk-…` — это уже утечка, и её надо убрать, а не замаскировать.

### Что не коммитить

- `node_modules/` — есть в `.gitignore`
- собранные бинари — есть в `.gitignore`
- `zen-router-old` — отдельный каталог, не часть этого репозитория

## Сообщения коммитов

На английском, содержательные. Первая строка: тип и суть.

```
feat: add the capacity to fall back to a second key
fix: the token must wrap both surfaces, not just control
test: add the recorded refusal and cover it
docs: describe the provider axes
```

Тело отвечает на **почему**, а не на что: причина, измерение, отвергнутая
альтернатива. Коммит, который только пересказывает дифф, бесполезен через месяц.

## Проверка перед объявлением готовности

«Собралось» — не доказательство. Перед словами «готово» нужен прогон, а для
изменений, затрагивающих провод или поверхности, — **живая проверка**:

```sh
/tmp/providermux up &
curl -s http://127.0.0.1:8787/_control/status
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8787/v1/models
```

Измеренный факт важнее рассуждения о нём. В этом репозитории живой прогон уже
дважды находил дефект, которого не видели тесты: счётчики не сохранялись на
диск, и токен не закрывал поверхность моделей.

## Правила самого проекта

- **Шлюз повторяет запрос только там, где это его решение.** По умолчанию —
  одна попытка: повторов нет, и `retry.attempts` поднимает их явно. Повтор
  разрешён ровно для двух случаев, которые клиент закрыть не может: обрыв
  транспорта до ответа и исчерпанная квота бесплатного канала. Квота повторяется
  только вместе со сменой адреса выхода (`rotation`), потому что её счётчик
  привязан к адресу; без ротации отказ уходит клиенту дословно. Отказ ключа,
  битый запрос и отказ по содержимому не повторяются никогда.
  Ротация принадлежит транспорту, а не демону: `rotation.transport` называет,
  за каким транспортом стоит селектор (по умолчанию — транспорт деплоя), и
  отказ провайдера, который едет другим путём, уходит клиенту дословно.
  Наблюдаемый адрес — свойство пути, а не хоста, поэтому у каждого транспорта
  свой резолвер, и счётчики провайдера считаются по адресу его пути.
  Основание: эталонный клиент считает `QuotaExceeded` неповторяемым
  (`packages/ai/src/schema/errors.ts`), а плагин DSH отключает свои повторы на
  маршруте `opencode` — выше шлюза повторов не остаётся.
- **Список узлов собирает сам демон.** `egress_refresh` запускает сборщик,
  загружает новый файл через контроллер и возвращает группу на первый узел;
  внешний таймер поверх этого — второй владелец, который перезапускает ядро и
  рвёт туннели. `out` обязан совпадать с домашним каталогом ядра: reload
  отвергает путь вне `SAFE_PATHS`.
- **Отказ передаётся дословно.** Статус, тело и заголовки — без изменений.
  Клиент ищет в теле признаки, по которым принимает решение.
- **Три ортогональные оси:** `provider` (что за сервис), `capability` (как
  обходить), `transport` (куда уходит трафик). Не смешивать.
- **Новый провайдер не должен требовать правки ядра.** Для
  OpenAI-совместимого сервиса достаточно секции в конфигурации.
- **Весь текст в коде — на английском.** Комментарии, сообщения об ошибках,
  строки для пользователя, имена тестовых случаев. Так было не всегда: раньше
  комментарии писались по-русски, и отголосок того правила остался ниже.
  Русский язык остаётся только для общения с владельцем репозитория.
